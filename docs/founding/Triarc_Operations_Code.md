# The Triarc Operations Code

*A reference draft, offered as a Triarc-specific addition to Contribution Code 2.3 (the sector list) and Contribution Code 8 (Positions), and to Founding Charter Article IV where it discusses Delegate Positions — not enacted law, and not applicable to any other deployment. The Triarc's own structural document, layered on top of the shared Charter and Contribution Code rather than replacing them, in the same spirit as the Triarc Membership Code. If ratified, amendable by the Triarc's own ordinary proposal, per the Rules of Procedure.*

---

## 1. Why the Triarc diverges from the Contribution Code's baseline sector lists

**1.1** Contribution Code 2.3 sets two founding-default sector lists: civic sectors for a deployment governing a municipality, and six organisational sectors — Infrastructure & Technology, Policy & Governance, Outreach & Membership, Finance & Treasury, Dispute & Conduct, Culture & Communications — for an organisation governing its own operations, each a starting point amendable by ordinary proposal per Contribution Code 2.2. Every other deployment continues under its baseline exactly as seeded. This document applies to the Triarc alone.

**1.2** The Triarc differs in kind, as Triarc Membership Code 1.2 already establishes. It is the nonprofit itself: a research organisation whose directors are elected and whose resource decisions are approved through this deployment. The six organisational sectors were written for an open community organisation, whose work is deliberation, culture and outreach in general. The Triarc's work is narrower — it studies whether the model works by running a real governance research organisation, with software stewardship in service of that research — and its sector list says so directly.

**1.3** This document applies the reasoning the Contribution Code already invites at 2.1, where domain shares rebalance quarterly by ordinary proposal, and at 2.3, where the sector list is amendable the same way.

## 2. The Triarc's three sectors

**2.1** In place of Contribution Code 2.3's six organisational sectors, the Triarc's sector list is, in order of standing priority:

| Sector | What it covers |
|---|---|
| **Data Collection & Research** *(lead sector)* | The Triarc's primary output: synthesis and quarterly publication of its own governance data — delegation-renewal completion rates, Dispute Panel outcomes, treasury and dividend arithmetic — on the fixed cadence *About The Triarc* commits to; engagement-metrics review; academic and philanthropic research partnerships as the Triarc's track record grows. |
| **Nonprofit Operations** | Treasury and finance administration, membership growth and outreach, conduct and Dispute Panel service, Rules of Procedure logistics (proposal administration, voting-window operations), culture and communications. Running the organisation day to day. |
| **Software Stewardship** | Platform development, infrastructure and hosting, security, the open-source contribution pipeline, and technical governance of the codebase — distinct from governance of the organisation, which lives under Nonprofit Operations. |

**2.1a** "Lead sector" is a statement of standing priority and identity, not a weighting mechanism. It does not change how Contribution Marks accrue, how the diversity cap or reciprocity damping apply, or how sector-scoped delegation and standing work (Contribution Code 2.2, 4). A Position in any of the three sectors is installed and recognised identically.

**2.2** These three replace, rather than add to, the six organisational sectors on the Triarc. A contribution, proposal, or opportunity that would have carried an old sector tag carries the corresponding new tag instead — "Infrastructure & Technology" becomes "Software Stewardship". Contribution Code 2.2's mechanics are untouched. Scope does change: because five of the six organisational sectors fold into Nonprofit Operations, a delegation granted for one of them now covers all of them. A Member who delegated on Culture & Communications holds a delegation that also reaches treasury and dispute matters. Such delegations carry over rather than lapsing. Any deployment performing this merge with live delegations must tell its Members before it runs, not after.

**2.3** This list is a default, adjustable by the Triarc's own ordinary proposal like any other parameter in this document.

## 3. The Triarc's three Delegate Positions

**3.1** Contribution Code 8.1 defines a Position as a named, defined office within a sector, filled when a Civic Steward becomes a Delegate for that sector under a ratified Position decision (Founding Charter 4.3, Rules of Procedure 1.5). With three sectors, the Triarc's Position set is three lead Delegate roles, one per sector:

- **Research Delegate** — Data Collection & Research
- **Operations Delegate** — Nonprofit Operations
- **Software Delegate** — Software Stewardship

These three are what Treasury Code 5.1's Foundation Dividend activation condition refers to for the Triarc: "every Delegate Position it has defined" means all three, filled by ratified Position decision. A deployment running either founding-default list (Contribution Code 2.3) reads that condition against its own Position list.

**3.2** Position mechanics are unchanged. Installation requires a ratified Position-decision vote at the three-fifths majority with 20% participation threshold (Rules of Procedure 1.3); the sustaining-floor recognition-lapse rule applies (Contribution Code, Founding Charter 4.7–4.9); and each Delegate may nominate Supporting Nominees under Contribution Code 8.2–8.8 exactly as written, including the eligibility, disclosure, and challenge rules there. This document narrows which sectors carry a Position, and nothing else.

**3.3** A Position is optional, not mandatory, exactly as the Contribution Code provides. A sector exists and accrues Contribution Marks whether or not a Member's standing in it has crossed the threshold that makes a Position decision available. The Triarc is not required to have all three Positions filled at any time — only that a filled Position is one of these three.

## 4. What this document does not do

**4.1** This document does not create, rename, or imply any legal corporate office. "Operations Delegate," "Research Delegate," and "Software Delegate" are Contribution Code Positions — recognised titles and operational roles under this platform's governance, per Contribution Code 8.4 — not directors under the Canada Not-for-profit Corporations Act. Triarc Membership Code 4.1 flags that tying corporate membership and director elections to the Triarc's own vote needs real legal review before the Triarc's bylaws can rely on it. This document does not resolve that review, and a future bylaw may or may not mirror these three Positions.

**4.2** This document does not change the Treasury Code's 40/40/20 split, and creates no per-sector budget line. Spending priorities within the Operations 40% will track these three functions in practice, but no new treasury-allocation requirement is created here.

**4.3** This document does not change anything about any other deployment. Their sector structure continues under Contribution Code 2.3 exactly as seeded.

**4.4** This document does not alter the Contribution Code's anti-gaming mechanics (Section 4). Reciprocity damping, novelty decay and the accrual cap apply on the Triarc exactly as anywhere else. The **diversity cap of Contribution Code 4.1 is measured on domains, not sectors**, and is unaffected: domains are fixed at four for every deployment, so cutting six sectors to three does not tighten it.

## 5. Implementation note

**5.1** Sectors are seeded once, at community creation, from a shared default list. Applying this document to the live Triarc deployment is therefore a one-time data change to existing records, not only a change to future defaults, and it is scoped and verified before it runs.

**Where does it fail?**

**5.2** **Schedule of defaults.** The one default in this code is **chosen** rather than derived. The operating sector list of Section 2 is a starting set, not a taxonomy: it names the work the Triarc actually has to do in its first year, and it is adjustable by the Triarc's own ordinary proposal. Expect it to be wrong in both directions — sectors nobody contributes to, and work nobody has a sector for — and expect the second kind to be the one worth acting on.
